# 安装排错

先看一条总规则：扩展只认 `http://127.0.0.1:3080`。DSH 没跑、端口不对、插件没挂上，都会表现成「没反应」。

先打开 `http://127.0.0.1:3080/page-chat/health` 看一眼，能省很多时间。

## 1. 工具栏上没有图标

**先查**：扩展到底装上了没有。

- Chrome 打开 `chrome://extensions`，看「随手问（Chrome / Edge）」在不在列表里，有没有红色「错误」。
- Firefox 打开 `about:addons`，看「随手问」在不在；临时载入的扩展在「临时附加组件」里。

**处理**：

- Chrome 新装的扩展常被收进拼图菜单。点地址栏右边的拼图图标，找到「随手问」，点图钉固定。
- 列表里没有，就重新「加载已解压」，目录选 `extension/`，不要选仓库根目录。
- 有红色错误，点「错误」看第一行；多数是 `manifest.json` 路径不对，或文件被移动过。
- Firefox 的临时扩展重启浏览器就会消失，重新走一遍 `about:debugging` 的临时载入。

## 2. 选中文字后没有浮标，或点浮标没反应

**先查**：当前页面能不能注入脚本。

- 浏览器内部页（`chrome://`、`about:`）、扩展商店、PDF 阅读器里，扩展不会注入，这是浏览器限制。
- 选中的字要 **2 个以上**；只选一个字不会出浮标。
- 打开开发者工具 Console，看有没有 `随手问` 相关的报错。

**处理**：

- 换一个普通网页（例如新闻站）再试。
- 刷新页面，让 `content.js` 重新注入。
- 还不行就重启浏览器；Chrome 的已解压扩展改文件后，要在扩展页点一次「重新加载」。
- 浮标出现但点不开，先确认 DSH 在跑：打开 `/page-chat/health`，`ok` 和 `dshReady` 都是 `true` 才算就绪。

## 3. 连不上 3080

**现象**：小框里提示「连不上 DSH（127.0.0.1:3080 没在跑？）」。

**先查**：

1. 终端里 `dsh web` 还在不在；关掉终端或按了 `Ctrl+C`，服务就停了。
2. 浏览器直接打开 `http://127.0.0.1:3080`，DSH 页面能不能出来。
3. 端口有没有被别的程序占用。

**处理**：

- 重新运行 `dsh web`，等它打印出地址再试。
- 当前版本把地址写死为 `127.0.0.1:3080`，没有改端口的设置；DSH 必须起在这个端口。
- 如果 DSH 起了但页面打不开，看终端报错；端口冲突就关掉占用 3080 的程序，或按 DSH 的说明改端口（改完扩展仍连 3080，所以不推荐）。

## 4. Firefox / Zen 重启后扩展消失

**这是临时载入的正常行为，不是坏了。**

`about:debugging` 里的「临时载入附加组件」只对当前会话有效，浏览器一关就清掉。

**处理**：

1. 重新在仓库根目录运行 `node build-firefox.mjs`，生成 `_dist-firefox/`。
2. 打开 `about:debugging#/runtime/this-firefox`。
3. 点「临时载入附加组件」，选 `_dist-firefox/manifest.json`。
4. 要用完就留着浏览器别关；重启后重复上面三步。

想要重启后还在，需要给扩展签名并正式安装，仓库没有提供这一步。

## 5. 插件装了，但 `/page-chat/health` 返回 404

**先查**：插件是不是挂进了 `dsh web` 用的那个 profile。

- 路由是插件注册的；插件没加载，DSH 只会回 404。
- 检查 `~/.dsh/profiles/web/package.json` 的 `dependencies` 里有没有 `@pydsl/dsh-page-chat`。
- 检查 `~/.dsh/profiles/web/node_modules/@pydsl/dsh-page-chat` 这个联接在不在，指向的 `plugin/` 目录存不存在。
- 检查 `~/.dsh/profiles/web/cordis.patch.yml` 里有没有 `id: page-chat` 那一条。

**处理**：

- 三处缺一处都不行，补完后 **重启 `dsh web`**，不是刷新浏览器。
- 看 `dsh web` 启动日志里有没有 `page-chat` 加载失败；路径写错、`cordis.patch.yml` 缩进错了，都会静默不加载。
- 确认你改的是 `web` profile；DSH 换了 profile，插件就不在。

## 6. 记忆没带上

**先分清是哪一侧。**

- **网页小框**：当前版本不会自动把旧记忆卡塞进新问题。它只带当前标签页里这段对话的上下文。旧卡主要给 DSH 主会话查。
- **DSH 主会话**：用 `memory_search` 按站点和关键词查卡，用 `memory_open` 打开原文。

**先查**：

- 侧栏「网页记忆」里有没有这张卡；点「记住这段」后按钮会变成「已记住 ✓（点一下撤销）」，5 秒内点它会把卡撤销。
- 记忆目录 `~/.dsh/page-chat-memory/cards/` 里有没有对应的 `.json` 和 `.thread.jsonl`。

**处理**：

- 没有卡：回到那段对话，再点一次「记住这段」。
- 有卡但搜不到：换关键词再搜；中文按两字切开比对，不是语义搜索。站点匹配会去掉 `www.`，同一站点下的子域不一定算同一个站。
- 刚写完卡就搜：确认 DSH 没在写盘中间被关掉；必要时重启 `dsh web` 再试。

## 7. 框选截图没反应

**先查**：

- 右键菜单里点的是「框选一块截图随手问」，不是「随手问这段」。
- 页面是不是浏览器内部页；这些页面不允许截图扩展注入。
- Firefox 第一次在某标签页截图时，可能要给临时权限；按提示允许，或刷新页面再试。

**处理**：

- 重新点一次菜单，等页面变暗后再拉框；拉完松开鼠标。
- 图太大可能超过 20MB 请求体上限，换小一点的区域。
- Chrome 系要靠点图标或右键菜单拿临时权限；如果反复失败，刷新页面后从右键菜单重新打开。

## 8. 回答很久才出来，或只出来一半

**这是当前实现，不是网络断流。**

扩展会等这一轮 NDJSON 收完，再在小框里逐字铺开。长回答的前几秒看起来像没动静；如果中途报错，会显示错误而不是半截答案。

**先查**：

- `/page-chat/health` 里 `dshReady` 是不是 `true`。
- 模型本身是不是在排队或超时；DSH 终端有没有报错。
- 问题是不是太长，或带了一张很大的截图。

**处理**：

- 等一会儿；超过模型超时时间会返回错误。
- 缩短问题、缩小截图，或换一个更快的模型。
- 如果一直停在半截，点小框里的「新对话」重开一段。刷新页面通常还会接着原来那段对话；要彻底重来，点「新对话」或关掉标签页再开。
